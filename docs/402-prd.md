**Product Requirements Document (PRD)**

---

**Title:**
Sensay Replica with x402 Crypto Paywall

---

**Problem Statement:**
Conversational agents like Sensay Replicas typically operate on a free-to-use basis. This limits direct monetization strategies and does not integrate well with crypto-native payment models. There is a need for a simple, secure, and composable method to charge users per interaction, leveraging existing crypto payment infrastructure.

---

**Solution Overview:**
Use Coinbase's x402 protocol to require crypto payment before executing a Sensay Replica response. The integration acts as a proxy, enforcing HTTP 402 (Payment Required) patterns and validating proof-of-payment before forwarding the user request to Sensay.

---

**User Flow:**

1. User enters a message in the UI.
2. Message is POSTed to a middleware backend.
3. Middleware checks for valid x402 payment receipt:

   * If **missing or invalid**, responds with HTTP 402 and a `Pay:` header containing a crypto invoice.
   * If **valid**, forwards the message to the Sensay API.
4. Middleware returns the Sensay response to the frontend.
5. User sees the AI-generated reply.

---

**Endpoints:**

* `POST /chat`: Main entrypoint for chat messages.

  * Accepts message + optional x402 headers
  * Returns `200 OK` with Sensay response or `402 Payment Required`

---

**Security & Limitations:**

* Sensay API key and Org ID never exposed to client.
* Proxy handles all request validation and signing.
* Optional: Rate-limit repeated unpaid access attempts.

---

**Technical Stack:**

* **Backend Proxy**: Node.js / Express or Python / FastAPI
* **x402 Handling**: Coinbase CDP SDK or manual header logic
* **Frontend**: HTML/CSS + minimal JS or React (SPA)
* **Data Store**: Redis / In-memory / Session cache
* **Environment**: Windsurf agentic development environment

---

**UI Components (MVP):**

* `textarea`: User message input
* `Send button`: Submits message
* `Response box`: Displays Sensay response
* `Payment prompt`: QR or payment link (if 402 received)
* `Loading indicator`: Shows during request
